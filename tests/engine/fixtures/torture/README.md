## Which master a fixture runs on

There is no `manifest.json` in this directory: the families deliberately span two masters, so each
`expect.json` names its own. Resolve it like this — three lines, no helper to import:

```python
expect   = json.loads((torture / f"{family}.expect.json").read_text("utf-8"))
manifest = Manifest.load(config.MASTERS_FIXTURE / f"{expect['master']}.manifest.json")
layout   = manifest.layout(expect["layoutId"])              # background PNG:
layout_png = config.MASTERS_FIXTURE / expect["master"] / "layouts" / layout.background
```

Every family but one sits on `test-16x9` (1280 × 720); `sizes-4x3` sits on `test-4x3` (960 × 720) and exists
only to prove the same IR lands correctly on a different canvas.

> `python -m engine reference engine/fixtures/torture` renders this directory: it resolves each slide
> through `engine.fixtures.context_for`, which reads the family's own `expect.json` for its master and
> layout, and writes `reference/<family>.png`. (WP0b's note that the CLI needs one `manifest.json`
> per directory predates `context_for` and no longer holds.)

## What each `expect.json` says

| key | meaning |
|---|---|
| `master`, `layoutId` | which master and layout the slide is designed against |
| `canvas` | the canvas the HTML is authored at; must equal the master's |
| `kinds` | element count per IR kind on the extracted IR — the headline assertion (`judge_family`); a kind the family does not list must be absent (`test_torture.test_every_family_has_only_its_listed_kinds_and_groups`) |
| `groups` | number of `groups` entries on the extracted IR, held by the same test when present |
| `rasterAllowed` | reasons a `raster` element may legitimately carry, matched as a case-insensitive substring. Empty means **zero rasters allowed** |
| `charts` | `{authored, recognised}` — how many chart elements the pipeline must end up with |
| `elements` | one entry per expected element, in document order, with the numbers worth asserting and a note saying why the case exists. Diagnostic, not exhaustive: `kinds` is the contract. An entry's `placeholder` (a `{type, idx}` or `null`) and its `startsWith` are asserted after classification (`test_torture.test_the_listed_placeholders_are_the_mapped_ones`) |
| `expectedDiagnostics` | `{level, match}` pairs the extraction must report; `match` is a substring of the message. Enforced by `engine/verify/torture.py: judge_family`: every listed pair must appear, and an `error` diagnostic or a `text-overflow`/`text-overlap` one that is not listed fails the family |
| `expectedLint` | `[{level, rule, count}]`: exactly that many static lint findings; any other lint `error` fails the family. A listed `chart-spec` error also accounts for the `IR.validate()` problem the same rejected spec raises on its chart element — one finding, reported twice (`chart-specs` keeps two such specs on purpose; `engine/verify/torture_expect.py`, G-2); `test_fixtures` subtracts the listed errors from its lint-clean and spec-valid checks |
| `gateMaxPx2` | the family's ceiling on the masked gate area (px²), read with **`is not None`** semantics: `0` means pixel-clean, absent means `config.gate_target_px2` for the canvas. Set at the measured area + 20 % with the number, the date and the cause in `notes` (Peter #16) — never to hide a regression |
| `notes` | the reasoning behind the counts — read this before arguing with a number |
| `lineage` | where a promoted family came from (`"fidelity probe p07_media cases B-E, 2026-09-24 …"`) |

Extra keys appear where a family needs them (`charts_expected` and `refused` on `svg-charts`,
`placeholdersUsed` on `placeholders`). Unknown keys are safe to ignore.

## References and their freshness

`reference/<family>.png` is the browser composite a family's export is gated against, rendered in the
family's **master fonts** (`render_reference(…, fonts=manifest.fonts)`; before WP-G every reference was
Arial). `reference/manifest.json` records, per family, `{htmlSha256, fonts, renderedAt}`; the sha256 is
of the HTML with line endings normalised. `python -m engine reference engine/fixtures/torture` (or
`python -m engine torture --reference`) writes both. `python -m engine torture` refuses a family whose
reference is missing, or whose entry names other HTML or other fonts ("reference stale"), and
`test_fixtures.py::test_torture_references_are_fresh` does the same in the suite: whoever changes a
family's HTML re-renders its PNG and commits it with its manifest entry (plan D13, §16 #14).

## Rules these fixtures pin down

**1. The element-boundary rule applies to in-flow siblings that stack.** `01-MASTER-BRIEF.md` §11 (as
amended by WP-B) defines a text element as "a maximal run of consecutive, vertically stacked, horizontally
overlapping in-flow sibling blocks and anonymous inline runs … atomic inline boxes with their own horizontal
geometry are elements of their own". An out-of-flow block (`position: absolute`) always starts its own
element — otherwise every real slide would be one element, the contract making its blocks absolutely
positioned siblings of `<body>` — and the run rule governs what happens *inside* it. Inside, blocks that sit
side by side (flex and grid rows, a number beside its unit) are one element each, and a padded chip leaves
its paragraph. `text.html` and `rows.html` are built around that reading and their `expect.json` files count
it that way.

**2. Overlap for placeholder mapping is measured against the text element's box.** `Box.overlap_fraction`
returns the share of *this* box covered by the other one, so a small caption fully inside a large zone
is 100 %, not 6 %. `placeholders.html` carries one case at 13.3 % that must stay unmapped.

**3. A multicol block yields one text element per column box that received at least one line, in
column order** (WP-F). A paragraph that straddles a column break is one paragraph in each element; a
`column-span: all` block is its own element at full width; a column the content overflowed into beyond
the declared count is an element too (beside the box, with a warn) unless an `overflow: hidden` on the
multicol hides it. `as-seen.html` block C counts two elements for `.cols` and three for `.cols3`.

## The promoted fidelity probes

Nine families are the fidelity plan's probes (`docs/engine/fidelity/01-FINDINGS.md`), promoted by WP-G
(G-2) once the fix packages had merged; `engine/fixtures/fidelity/probes/` is gone. Each keeps its probe's
HTML except for what its `notes` say changed: the `.h` headings are `width:872px`, to the right edge of
layout-06's title zone (a shrink-to-fit bold title in the Calibri Light major overhangs in PowerPoint because
`test-16x9`'s theme part names Calibri as major — the masters' mismatch, not the families' subject); `media` drops the
probe's remote `<img>` (case A lives in `engine/tests/test_extract_as_seen.py`); `weights`' clipped card
gained the copy that makes it overflow in Calibri, and its tight card the copy that brings its last line to
the card's clip edge. p05 (waterfall totals, a bridge across zero) and p11
(an axis near 3,400, negative bars) are not families of their own: `charts-hardening` (A–C, H) and
`charts-negative` (D, F) already carry their six specs verbatim, in re-cut frames (chart frames are masked, so
no gate number depends on them). The same title mismatch is all of the gate area of `flexgrid`,
`tables-cells`, `pseudo`, `colours`, `chart-specs` and `layout-misc` and 5,195 of `weights`' 5,271 px², but
only 30 % of `media`'s (the rest is emoji, which PptxRender draws as boxes; the engine's collapsed `&nbsp;`
spacing and lost arrowheads went with r1b) and 14 % of `text-misc`'s (gradient text, PptxRender); each
`gateMaxPx2` note breaks its number down and names the engine's share where there is one.

Title placeholders on these families are mapped by the heading's `data-placeholder`, which the extractor
records since render-check R3 and `map_placeholders` pass 1 honours; unmarked text is mapped by geometry
(pass 2, ≥ 60 % of the box inside the zone). So `chart-specs`' heading, not its caption A, is the title
placeholder, and so is `layout-misc`'s 1232 px title, at its own measured rect. Both are asserted, not only documented: an `elements[]` entry that names
a placeholder (or `null`) and its `startsWith` are held by
`test_torture.test_the_listed_placeholders_are_the_mapped_ones`; `kinds` is a family's whole inventory and
`groups` its group count (`test_every_family_has_only_its_listed_kinds_and_groups`).

## Deliberate omissions

Each of these is a construct the contract allows but no fixture exercises, because the expected IR is
genuinely undecided and a fixture that guesses would just make somebody's test wrong:

- **Nested lists.** `<li>` containing both inline content and a nested `<ul>` is not inline-only, so the
  boundary rule decomposes a five-item nested list into **four** text elements (the items before the
  mixed one, that item's own inline content, the nested items, the items after). That is almost
  certainly not what the emitter wants — one text box with `lvl` per paragraph is. Needs a decision
  before a fixture can assert anything. Every list here is flat.
- **Two `box-shadow` layers.** The contract allows up to two outer shadows; `ir.shadow` holds one.
  `boxes.html` has the case (`shadow-two`) and `boxes.expect.json` records the expected behaviour —
  keep the outermost, drop the second with a `warn` — but the schema, not this fixture, should settle it.
- **`.svg` in `<img>`.** `02-IR-SCHEMA.md` §image says the extractor rasterises it to a PNG and the
  element stays kind `image`; `11-WP1`'s table calls it an "isolated raster". `images.expect.json`
  follows the schema (kind `image`, `src` pointing at the derived PNG, one `warn`).

## `ir/*.json` — the hand-written IRs

A small authored IR per family so WP3 and WP4 can emit and test before WP1/WP2 land a real extractor.
They are *not* transcripts of the matching HTML: they hold at least one element per construct and
nothing else. `make_ir.py` writes them through `engine.ir`'s dataclasses and refuses to save anything
that fails `IR.validate()`.

**`image.src` and `raster.src` are repo-relative, POSIX style** (`engine/fixtures/torture/assets/...`).
The schema calls for absolute paths, but a committed fixture cannot carry this machine's drive letter.
Resolve before use:

```python
ir = IR.load(path)
for element in ir.elements:
    if element.src and not Path(element.src).is_absolute():
        element.src = str((config.PROJECT_ROOT / element.src).resolve())
```

`make_ir.py` is the source these were generated from, not a build step: if you hand-edit a JSON, the
script goes stale, and nothing enforces that it does not. Re-run it only if you also fold your edit
back into it.

## Regenerating

```
python engine/fixtures/torture/make_assets.py     # the image assets (deterministic)
python engine/fixtures/torture/make_ir.py         # the hand-written IRs (deterministic)
python engine/fixtures/masters/make_test_masters.py   # the two test masters + their layout PNGs
```

Assets are drawn from code — a four-quadrant card with corner ticks at 400 × 300 (PNG), 300 × 400
(JPEG) and a 160 × 160 RGBA mark — so every `object-fit` crop is legible at a glance and no file
carries a licence.
